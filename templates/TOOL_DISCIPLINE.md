# GLM tool-use discipline

These are execution rules, not additional authority. Current assignment, tool
schemas, permissions and safety boundaries still control all actions.

1. A successful read is information already acquired. Use its result to choose
   the next different causal action. Before repeating a command, identify changed
   input or a new question. Without either, reuse its result; never issue a third
   identical successful read of unchanged content. Alternating two reads is also
   repetition, not progress.
2. After at most eight consecutive inspection calls, consolidate the facts in
   reasoning and choose an edit, a decisive bounded check or one precise missing
   dependency. Further inspection must answer a genuinely new required question.
   This does not limit necessary research or reduce assigned scope.
3. Follow the available tool schema exactly. Use contextual apply_patch edits.
   After a syntax failure, read the faulty function and repair the construct;
   never blindly append braces or repeat broad string replacements. Use supplied
   generators rather than manually modifying generated output. Patch/diff files
   are generated artifacts: create them mechanically with diff/git diff against
   preserved preimages (difference exit1 is expected), never hand-author or patch
   their hunk headers, context prefixes or checksums. If packet formatting blocks
   handoff, preserve changed source and report that exact packaging gap to root.
4. Never pipe a proof command into head, tail or another command that hides its
   exit status. Run it directly with bounded tool output, or save its full log and
   capture its status BEFORE displaying a bounded excerpt. A truncated error is
   not enough information to choose a repair; read the actual error first.
5. The same failure twice on unchanged relevant input requires a different causal
   hypothesis/action. If none is justified, checkpoint the precise blocker for
   root, preserve files and do not claim completion.
6. Poll only a handle returned by a still-running command. A legitimate wait is
   not a new run. Never relaunch because output is delayed.
7. Update the existing checkpoint after meaningful decisions, edits and proofs,
   and before long commands. No extra report per call. Resume from assignment and
   checkpoint; verify only potentially changed facts, not the whole history.
8. GLM_TOOL_LOOP_READ_ONLY and GLM_TOOL_LOOP_SELF_HASH are local non-progress
   stops, not provider errors. Await a corrected root envelope; do not resend
   unchanged history or change provider to evade them.

Handoff lists actual changes, observed checks and remaining gaps. A successful
micro-test is not broad task acceptance.

Fingerprints are measured tool output, never text to guess or compute mentally.
Run shasum/sha256sum (or an existing trusted fingerprint helper) on the exact files
before recording a fingerprint. If a prior fingerprint was not measured, label it
UNMEASURED and do not reuse proof through it; preserve observed test counts and
report the evidence limitation rather than inventing an identity.
